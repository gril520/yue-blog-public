前端项目打包部署 ​

零、路由路径和打包路径需一致 ​

是的，在 Vue 项目中，路由的 base 配置和打包配置的 publicPath 需要保持一致，才能确保线上部署时资源加载和路由跳转正常工作。以下是详细说明：

1. 路由配置 (base) ​

javascript
const router = new Router({
  base: '/baseplatformh5', // 路由基础路径
  mode: 'history',        // 去掉 URL 中的 `#`
  routes: dynamicRouter
});
1
2
3
4
5
  • 作用：指定应用的基路径。所有路由会在该路径下匹配（例如 /baseplatformh5/home）。
  • 关键点：
    • 如果应用部署在域名的子路径下（如 https://example.com/baseplatformh5），必须设置 base 为该子路径。
    • 如果 base 为空或 /，则路由会从根路径开始匹配。

2. 打包配置 (publicPath) ​

javascript
// vue.config.js
module.exports = {
  publicPath: '/baseplatformh5', // 部署的子路径
  outputDir: 'dist',
  assetsDir: 'static',
  filenameHashing: true
};
1
2
3
4
5
6
7
  • 作用：定义静态资源（JS、CSS、图片等）的引用路径。
  • 关键点：
    • publicPath 必须与路由的 base 一致，否则打包后的资源加载会 404。
    • 如果使用 history 模式，publicPath 还会影响 HTML5 History API 的根路径。

3. 为什么需要一致？ ​

  • 资源加载：打包后的静态资源（如 app.js）会通过 publicPath 拼接 URL。如果 publicPath 是 /baseplatformh5，资源会从 /baseplatformh5/static/js/app.js 加载。

  • 路由匹配：路由的

    base
    1

    决定了前端路由的起始路径。如果两者不一致，可能导致：

    • 路由跳转正确，但资源加载失败（404）。
    • 资源加载正确，但路由跳转 404（因为服务器未配置路由回退）。

4. 线上部署注意事项 ​

  1. 服务器配置：

    • 确保服务器（如 Nginx、Apache）将 /baseplatformh5 的请求正确指向你的应用目录（如 dist）。
    • 对于 history 模式，需配置服务器重定向所有子路径到 index.html（避免刷新 404）。

    Nginx 示例：

    nginx
    location /baseplatformh5 {
  alias /path/to/dist;
  try_files $uri $uri/ /baseplatformh5/index.html;
}
    1
    2
    3
    4

  2. 动态 publicPath：

    • 如果子路径可能变化（如多环境部署），可以通过环境变量动态设置

      publicPath
      1

      ：

      javascript
      // vue.config.js
module.exports = {
  publicPath: process.env.VUE_APP_BASE_PATH || '/'
};
      1
      2
      3
      4

  3. 根路径部署：

    • 如果应用部署在域名根路径（如

      https://example.com
      1

      ），则设置：

      javascript
      base: '/',
publicPath: '/'
      1
      2

5. 常见问题 ​

  • 资源 404：检查 publicPath 是否与实际部署路径一致。
  • 路由 404：确保服务器配置了 history 模式的回退，且 base 与路径前缀匹配。
  • 开发环境：本地开发时如果修改了 base，可能需要配置开发服务器的代理或路径。

总结 ​

  • 必须一致：路由 base 和 publicPath 的值应相同（如均为 /baseplatformh5）。
  • 服务器适配：确保服务器配置支持子路径和 history 模式。
  • 动态环境：通过环境变量管理不同环境的路径配置。

这样能避免大部分部署后的路径问题。

  • 生产环境必须启用 HTTPS，并配置 HSTS 头防止降级攻击：

  ssl_certificate_key /path/to/key.pem;
