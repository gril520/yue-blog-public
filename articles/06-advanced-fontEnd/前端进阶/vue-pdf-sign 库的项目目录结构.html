javascript
function createLoadingTask(src, options) {
  var source;
  if (typeof(src) === 'string')
    source = { url: src };
  else if (src instanceof Uint8Array)
    source = { data: src };
    
  var loadingTask = PDFJS.getDocument(source);
  loadingTask.__PDFDocumentLoadingTask = true;
  
  return loadingTask;
}

this.loadDocument = function(src) {
  pdfDoc = null;
  emitEvent('num-pages', undefined);
  
  pendingOperation = pendingOperation.then(() => {
    var loadingTask = isPDFDocumentLoadingTask(src) 
      ? src 
      : createLoadingTask(src, {
          onPassword: (updatePassword, reason) => {
            emitEvent('password', updatePassword, reasonStr);
          },
          onProgress: (status) => {
            emitEvent('progress', status.loaded / status.total);
          }
        });
    
    return loadingTask.promise;
  })
  .then(pdf => {
    pdfDoc = pdf;
    emitEvent('num-pages', pdf.numPages);
    emitEvent('loaded');
  })
}

this.renderPage = function(rotate) {
  var pageRotate = (pdfPage.rotate || 0) + (rotate || 0);
  var scale = canvasElt.offsetWidth / pdfPage.getViewport({ scale: 1 }).width 
              * (window.devicePixelRatio || 1);
  var viewport = pdfPage.getViewport({ scale, rotation: pageRotate });
  
  canvasElt.width = viewport.width;
  canvasElt.height = viewport.height;
  
  pdfRender = pdfPage.render({
    canvasContext: canvasElt.getContext('2d'),
    viewport: viewport
  });
  
  // 渲染注释层（链接、表单等）
  pdfPage.getAnnotations({ intent: 'display' })
    .then(annotations => {
      PDFJS.AnnotationLayer.render({
        viewport: viewport.clone({ dontFlip: true }),
        div: annotationLayerElt,
        annotations: annotations,
        page: pdfPage,
        linkService: linkService
      });
    });
}

CMapReaderFactory.js - 中文字体映射加载器 🌏 ​

javascript
import { CMapCompressionType } from 'pdfjs-dist-sign/es5/build/pdf.js'

export default function() {
  this.fetch = function(query) {
    return import('./buffer-loader!pdfjs-dist-sign/cmaps/' + query.name + '.bcmap')
      .then(bcmap => ({
        cMapData: bcmap.default,
        compressionType: CMapCompressionType.BINARY
      }));
  }
}

Vue渲染函数 ​

非常好的问题！你提到的这些知识点确实有些抽象，尤其是对初学者来说。我们来从零开始、用通俗易懂的方式解释你最关心的部分：

问题聚焦：“渲染函数（render(h)）是 Vue 的还是 JS 的？作用是什么？” ​

简短回答： ​

render(h) 是 Vue 提供的一种写组件的方式，底层基于 JavaScript，但它属于 Vue 的 API。它的作用是：用 JS 代码直接创建虚拟 DOM（而不是写 <template>）。

详细拆解 ​

    <h1>{{ msg }}</h1>
  </div>
</template>

<script>
export default {

    return { msg: 'Hello!' }
  }

h 是什么？ ​

  • h 是 hyperscript 的缩写（历史术语）
  • 它是一个函数，用来创建 虚拟 DOM 节点（VNode）
  • 在 Vue 2 中，它是 createElement 的别名
  • 在 Vue 3 中，它来自 import { h } from 'vue'

你可以把它理解为：“帮我造一个 HTML 元素” 的工具函数。

js
h('标签名', { 属性对象 }, [子元素列表])
1

例子：

js
h('div', { id: 'app' }, [
  h('span', '你好'),
  h('button', { onClick: this.handleClick }, '点击')
])

为什么需要 render 函数？ ​

优势场景： ​

场景说明
动态结构模板写死结构，但 render 可以用 if/for 灵活生成
高阶组件封装通用逻辑（如 componentFactory.js）
性能优化避免模板编译开销（但现代 Vue 已优化，差别不大）
JS 能力更强可以用函数、变量、计算逻辑直接控制 DOM

举个实际例子（来自你的项目）： ​

在 componentFactory.js 中：

js
render(h) {
  return h('span', { style: 'position: relative; display: block' }, [
    h('canvas', { ref: 'canvas' }),
    h('span', { class: 'annotationLayer' }),
    h(resizeSensor, { on: { resize: this.resize } })
  ])
}

👉 这里必须用 render 函数，因为：

  • 它是一个工厂函数，要动态生成不同配置的组件
  • 要插入第三方组件 resizeSensor
  • 要绑定 ref 和事件监听器
  • 用 <template> 很难做到这种灵活性

它是 Vue 的还是 JS 的？ ​

  • 语法是 JS：你写的是 JavaScript 函数
  • 语义是 Vue 的：h() 是 Vue 提供的 API，返回的是 Vue 的 VNode
  • 运行时依赖 Vue：没有 Vue，这段代码毫无意义

所以：它是 Vue 框架提供的一种基于 JavaScript 的组件编写方式。

类比理解（帮助记忆） ​

概念类比
<template>像“画图纸”——你描述想要的房子长什么样
render(h)像“亲自盖房子”——你用代码一块砖一块砖地搭建
h() 函数就是你的“砌砖工具”

补充：什么时候该用 render？ ​

✅ 推荐用❌ 不推荐用
写 UI 库、组件库（如 vue-pdf-sign）普通业务页面

Webpack 和 Loader ​

当然可以！我们来用通俗易懂的方式，结合你看到的 vue-pdf-sign 项目中的实际例子，详细讲解这三个 Webpack 相关的核心概念：

一、什么是 Webpack？ ​

先简单说一句：

Webpack 是一个“打包工具” —— 它把你的 .js、.vue、.css、图片、字体等文件，打包成浏览器能运行的代码。

而 Loader（加载器） 就是 Webpack 的“翻译官”：

  • 浏览器不认识 .vue 文件 → vue-loader 来翻译
  • 浏览器不认识 TypeScript → ts-loader 来翻译
  • 浏览器不认识 Web Worker 文件 → worker-loader 来处理

自定义 Loader 开发 ​

你在项目中看到的例子： ​

js
// CMapReaderFactory.js
import('./buffer-loader!pdfjs-dist-sign/cmaps/UniGB-UTF16-H.bcmap')

这里用了 buffer-loader!xxx.bcmap —— 这就是自定义 Loader！

什么是自定义 Loader？ ​

当你遇到 Webpack 默认不支持的文件类型（比如 .bcmap 字体映射文件），你可以自己写一个 Loader 告诉 Webpack：“这种文件该怎么处理”。

项目中的 buffer-loader.js 长这样： ​

js
// src/buffer-loader.js
module.exports = function(content) {
  var data = content instanceof Buffer ? content : Buffer.from(content);
  return 'export default Buffer.from("' + data.toString('base64') + '", "base64")';
}
module.exports.raw = true; // 表示按二进制读取

2
3
4
5
6

它做了什么？ ​

  1. 接收一个二进制文件（如 xxx.bcmap）
  2. 把它转成 Base64 字符串
  3. 输出一段 JS 代码：export default Buffer.from("...", "base64")
  4. 这样，JS 就能直接“内嵌”这个二进制文件了！

类比理解： ​

想象你要把一张照片放进 Word 文档：

  • 普通方式：插入图片链接（外部文件）
  • Loader 方式：把照片直接粘贴到文档里（内嵌）

buffer-loader 就是把 .bcmap “粘贴”进 JS 里，避免额外 HTTP 请求。

什么时候需要自定义 Loader？ ​

  • 处理特殊格式文件（.wasm, .proto, .bcmap 等）
  • 预处理资源（压缩图片、加密配置等）
  • 转换非标准语法

普通 import vs 动态 import ​

类型写法特点
静态 importimport foo from './foo.js'打包时就确定，所有代码一起加载
动态 importimport('./foo.js').then(...)运行时才加载，可实现“按需加载”

在项目中的作用： ​

  • 中文字体映射文件有上百个（UniGB-..., UniCNS-... 等）
  • 用户可能只看中文 PDF → 只需要 UniGB-UTF16-H.bcmap
  • 用 import() 只在需要时才下载这个文件，而不是一次性加载全部！

什么是 Web Worker？ ​

Web Worker 是浏览器提供的“多线程”能力 —— 让耗时任务（如解析 PDF）在后台运行，不卡住页面。

但问题来了：

  • Worker 必须从 独立的 JS 文件 启动
  • 你不能直接 new Worker('inline code')

那怎么把 pdf.worker.js 变成 Worker？ ​

这就是 worker-loader 的作用！

worker-loader 做了什么？ ​

  1. 把 pdf.worker.js 打包成一个独立的 JS 文件（或 Data URL）

  2. 返回一个 可 new 的构造函数

  3. 你就可以像这样使用：

    js
    const MyWorker = require('worker-loader!./my-worker.js');
const worker = new MyWorker(); // ✅ 成功创建 Worker！
    1
    2

项目中的实际流程： ​

js
// 1. 引入 worker-loader 处理的 worker 文件
var PdfjsWorker = require('worker-loader!pdfjs-dist-sign/.../pdf.worker.js');

// 2. 创建实例
var workerInstance = new PdfjsWorker();

// 3. 告诉 PDF.js：“用这个 Worker 解析 PDF”
PDFJS.GlobalWorkerOptions.workerPort = workerInstance;
