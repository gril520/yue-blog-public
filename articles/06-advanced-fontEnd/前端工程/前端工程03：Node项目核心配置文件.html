前端工程03：package.json ​

以下是对 package.json 中每个主要配置项的 逐项、无图标、纯文字详解，解释其作用和设计意图。

一、基础信息 ​

json
"name": "base-platform-front",
"version": "1.0.0",
"private": true
1
2
3
  • name: 项目名称，用于标识这个包。
  • version: 当前版本号（遵循语义化版本：主.次.修订）。
  • private: true: 表示这是一个私有项目，不会被发布到 npm 公共仓库。即使误执行 npm publish 也不会上传。

✅ 企业内部系统通常都设为 private。

二、scripts 脚本命令详解 ​

1. 安装相关 ​

json
"preinstall": "npx only-allow pnpm"
1
  • 在运行 npm install 或 yarn install 前触发。
  • 使用 only-allow 强制要求使用 pnpm 作为包管理工具。
  • 如果你用 npm 或 yarn 安装，会报错并提示：“请使用 pnpm”。

✅ 目的：统一团队依赖管理工具，避免 lockfile 冲突。

json
"postinstall": "husky install"
1
  • 安装完依赖后自动执行 husky install。
  • Husky 是 Git Hooks 工具，用于在提交代码时自动运行 lint、test 等检查。
  • 此命令会激活 .husky/ 目录下的钩子脚本（如 pre-commit、commit-msg）。

✅ 实现“提交即校验”，保障代码质量。

2. 开发与构建脚本 ​

json
"serve": "vue-cli-service serve"
1
  • 启动本地开发服务器（localhost:8080），支持热更新。
  • 默认读取 .env.development 环境变量。

✅ 日常开发最常用命令。

构建打包系列 ​

json
"build": "pnpm build-lib && vue-cli-service build --no-module"
1
  • 构建集团部署版本。
  • 先执行 build-lib（编译内部组件库），再进行主应用构建。
  • --no-module：禁用 ES Modules 输出（Vue CLI 特有参数，适用于传统浏览器环境）。
json
"build:independent": "pnpm build-lib && vue-cli-service build --mode independent --no-module"
1
  • 构建独立部署版本（关闭单点登录）。
  • --mode independent → 加载 .env.independent 文件中的配置（如 API 地址、是否启用 SSO）。
json
"build:independent-sso": "pnpm build-lib && vue-cli-service build --mode independent-sso --no-module"
1
  • 构建独立部署版本（开启单点登录）。
  • 使用不同的模式加载对应的环境变量文件（.env.independent-sso）。

✅ 多环境构建的核心机制：通过 --mode xxx 切换不同配置。

json
"build-lib": "pnpm -r --filter @leyue/* run build"
1
  • 使用 pnpm 的 workspace 功能，递归地（-r）找到所有以 @leyue/ 开头的包（如 @leyue/tr-ui），并对它们运行 build 命令。
  • 这些是公司内部的私有组件库或插件，在主项目构建前必须先编译好。

✅ 微前端或多包架构常见做法，确保依赖的本地模块是最新的。

json
"analy": "cross-env ANALY=1 vue-cli-service build --no-module"
1
  • 设置环境变量 ANALY=1，然后执行构建。
  • 通常配合 webpack-bundle-analyzer 插件使用，构建完成后会打开一个网页，展示各个模块的体积分布。
  • 用于分析包过大原因，优化拆包策略。

✅ 性能优化必备工具。

json
"test:unit": "vue-cli-service test:unit"
"test:unitc": "vue-cli-service test:unit --coverage"
1
2
  • 运行单元测试（基于 Jest）。
  • test:unitc 多了一个 --coverage，生成测试覆盖率报告（多少代码被测试覆盖了）。

✅ 提高代码可靠性，防止改出 bug。

json
"lint": "vue-cli-service lint"
"lint-staged": "lint-staged"
1
2
  • lint: 手动运行 ESLint 和 Prettier 检查并修复代码格式问题。
  • lint-staged: 对“暂存区”的文件（即将 commit 的文件）运行 lint，由 Husky 触发。

✅ 统一代码风格，减少低级错误。

json
"commit": "cz"
1
  • 使用 Commitizen 提供交互式提交界面。
  • 替代直接写 git commit -m "xxx"，引导开发者按规范填写提交信息（类型、范围、描述等）。

✅ 保证提交记录结构化，便于生成 changelog。

发布相关脚本 ​

json
"changeset": "changeset"
1
  • 初始化或添加一个 changeset 文件（.changeset/*.md），记录本次修改的影响（如功能新增、bug 修复、破坏性变更）。
  • 用于后续自动生成版本号和发布日志。
json
"version-packages": "changeset version"
1
  • 根据 .changeset/ 中的文件，自动更新 package.json 的版本号，并生成 changelog。
  • 不真正发布，只做本地版本管理。
json
"release": "pnpm build-lib && pnpm release:only"
1
  • 完整发布流程：先构建内部库，再发布所有 changed 包。
  • 适合 CI/CD 流水线中使用。
json
"release:only": "changeset publish --registry=http://10.99.180.187:8081/repository/npm-hosted/"
1
  • 将标记要发布的包推送到指定的私有 NPM 仓库（内网地址）。
  • 结合 Changesets 实现自动化版本管理和发布。

✅ 整套方案实现了：

  • 提交规范化（commit）
  • 变更可追踪（changeset）
  • 版本自动升级（version）
  • 私有包安全发布（publish）

三、config 配置块 ​

json
"config": {
  "commitizen": {
    "path": "cz-conventional-changelog"
  }
}
1
2
3
4
5
  • 配置 Commitizen 使用哪种提交模板。
  • cz-conventional-changelog 是最常用的规范，对应 Angular 风格提交消息（feat:, fix:, docs: 等）。

✅ 让 pnpm commit 命令知道如何引导用户输入标准格式。

四、dependencies 依赖说明（生产依赖） ​

这些是项目运行所必需的库。

包名作用
@leyue/tr-*公司内部开发的各类插件和组件库（UI、登录、请求、表格、富文本等），属于核心业务能力支撑
axiosHTTP 请求客户端
element-uiVue 2 的主流 UI 框架（含按钮、表单、弹窗等）
vue, vue-router, vuexVue 2 生态三大件
core-js提供 JavaScript 新特性的 polyfill（兼容老浏览器）
dayjs轻量级日期处理库
lodash.clonedeep深拷贝工具函数
file-saver / save-svg-as-png文件导出功能支持
vuedraggable拖拽组件（基于 Sortable.js）
crypto-js加密算法库（如 AES、MD5）
sql-formatterSQL 语句美化
clipboard复制文本到剪贴板
jquery虽然 Vue 不推荐，但某些旧插件仍依赖 jQuery
normalize.cssCSS 样式重置，消除浏览器默认样式差异

✅ 所有 @leyue/* 都是内部包，可能通过 Git Submodule、PNPM Workspace 或私有 Registry 管理。

五、devDependencies 开发依赖说明 ​

这些仅在开发和构建阶段需要，不包含在最终产物中。

包名作用
@vue/cli-serviceVue CLI 的核心服务，提供 serve、build 等命令
@vue/cli-plugin-*Babel、ESLint、Router、Vuex 等官方插件
@babel/*JavaScript 编译器，将 ES6+ 语法转为兼容老浏览器的代码
eslint + @leyue/eslint-config代码静态检查工具，使用公司统一规则集
prettier代码格式化工具
husky + lint-stagedGit 提交拦截器，实现自动 lint
commitizen + @commitlint/*提交信息规范化工具链
compression-webpack-plugin生成 gzip 压缩文件
terser-webpack-pluginJS 压缩混淆
sass + sass-loader支持 .scss 文件编译
svg-sprite-loader将多个 SVG 图标合并为雪碧图
jest + @vue/test-utils单元测试框架
cross-env跨平台设置环境变量（Windows/Linux/macOS 兼容）
rollup + @rollup/plugin-*用于构建 @leyue/* 类型的库（非应用）
@changesets/cli自动化版本管理和发布工具

✅ 这是一个非常完整的现代前端工程化技术栈。

六、总结：整体架构特点 ​

特性实现方式
多环境部署多个 build script + mode 切换
内部组件复用@leyue/* 私有包 + build-lib 预构建
代码质量保障Husky + Lint-Staged + ESLint + Prettier + Jest
提交规范化Commitizen + Commitlint
版本自动化Changesets 实现 changelog 与发布
包体积优化externals + CDN + splitChunks + Gzip
构建效率提升pnpm + workspace + 并行构建

这套 package.json 不只是一个依赖列表，而是整个项目的 工程化蓝图。它体现了：

  • 团队协作规范（提交、格式、测试）
  • 技术选型统一（Vue 2 + Element UI + PNPM）
  • 可持续交付能力（CI/CD 准备就绪）
  • 企业级复杂度应对（多环境、多模块、私有依赖）

每一行都不是随意写的，背后都有明确的设计考量。
